# 史莱姆爆炸碎块：方案 D

游戏侧边栏「类型 → 史莱姆爆炸碎块」控制此效果，默认开启。参数支持现有的「保存 JSON」流程。

爆炸触发时，将20 块大小不一的不规则曲面碎块映射到身体当时的顶点姿态，继承实际大小、弯曲、膨胀和颜色。碎块随后由物理 Shape Matching 求解器驱动，地面碰撞会压缩、拉伸节点，再由体积和形状约束恢复；没有用缩放动画代替软体。眼球、冲击波等原有爆炸效果继续触发。

## 调试

- **碎块软度**：越大越软；默认 0.8。
- **体积可压缩度**：越小越保体积；默认 0.05。
- **弹性阻尼**：越大越快停止内部振动。
- **局部形变平滑**：减轻局部折皱，过高会变硬。
- **物理子步 / 迭代**：增加可改善稳定性，同时增加 CPU 开销。
- **爆开速度倍率 / 内部速度差 / 初始旋转速度**：下一次爆炸生效；其余材料与地面参数作用于现有碎块。
- **保留时间 / 最多同时保留**：默认 6 秒、3 组，每组 20 块；超限回收最早一组。
- **地面摩擦**：默认 1，贴地接触点止滑，同时允许向上离地反弹；小于 1 时恢复可滑动的摩擦模式。
- **表面线框**：观察真实表面形变；关闭总开关立即清理碎块。

当前支持地面碰撞，未加入碎块之间、碎块与角色之间的碰撞。若身体爆炸前已有部分穿地，首个物理步将对应碎块移出地面，但不将这段校正计算为弹出速度。

## 实现与验证

物理以 60 Hz 更新，默认每步 8 个子步；高精度表皮由 GPU 按物理节点变形，每渲染帧只上传节点位移与四面体法线矩阵。每组共有 1,125 个物理节点与约 9.2 万表面三角形，连续爆炸开销由组数上限控制，尚未完成移动端性能评估。

`src/slime-fragments/` 包含求解器、表皮及实时姿态映射；`src/slime-fragment-effects.ts` 管理生成、更新和回收。`public/assets/slime-fragments/` 保存预切割资源；`tools/slime-fragments/bind-pose.py` 可离线重建姿态绑定。

验证：构建通过；碎块、爆炸颜色与箭矢相关 27 项测试通过；`node tools/slime-fragments-browser-check.mjs` 在 Chrome 验证生成、落地形变、参数保存、关闭清理、超限回收及重置。换模初始表面位置误差低于 0.000001 u。另有 4 项旧身体/眼球姿态测试失败，在未修改的 HEAD 基线上可复现。


## 性能优化（2026-11-10）

保留原有 9 块、876 节点、全部表面三角形与求解精度，未改动用户的软体参数。

- 求解器展开热点矩阵运算，复用临时数组，去除方案 D 不使用的四面体/边约束重置。
- 表面顶点和法线变形交给 GPU。每组每帧动态上传量从 1,760,568 字节降至 182,304 字节（约减少 90%）。出生时仍上传完整的实际身体姿态。
- 每组碎块共用 GPU 缓冲和一个绘制网格，将每个渲染通道的提交从 9 次减少到 1 次，各块物理状态仍独立。
- 按当前组数上限预热资源；复用物理约束和数组，按新姿态重算静止形状，减少爆炸时分配。启动后若再提高组数上限，新增槽位仍会按需创建。
- 初始姿态运行时诊断改为每块抽查约 128 个顶点；单元测试继续检查完整表面映射及 GPU 缓冲与 CPU 表皮的等价性。

本机三组（27 块）对照，保持 8 子步、1 次迭代：独立 CPU 基准中求解中位耗时从 16.28 ms 降至 7.01 ms，表皮更新的 CPU 耗时从 12.09 ms 降至 1.31 ms。连续模拟 240 步后，与优化前位置最大差异为 2.10e-9 u。

Chrome 游戏内、1440×1050、三组同时存在，预热 30 帧后采样 180 帧：整帧 CPU 中位耗时 53.2 → 21.0 ms，P95 58.2 → 22.6 ms；三组爆炸发生的单帧 CPU 耗时 217.1 → 60.4 ms。后者包括姿态映射、其他爆炸效果、渲染提交及测试快照，不能等同于单个碎块生成时间。数字不代表 GPU 完成耗时或所有设备的帧率。

复测入口：`npx tsx tools/slime-fragments/perf.ts /tmp/fragments-perf.json --gpu`；运行开发服务器后执行 `node tools/slime-fragments/perf-browser.mjs /tmp/fragments-browser-perf.json`。本次报告存于 `analysis/slime-fragments/perf-*.json`。

验证：构建、29 项相关单元测试、Chrome 生成/形变/保存/关闭/回收流程通过；最终姿态映射变更后重新运行全部 6 项碎块单元测试通过。


## 落地止滑（2026-11-10）

用户要求落地不滑动、仍可弹起。将「地面摩擦」默认值与当前保存值设为 1；满值时，求解器在地面接触投影中约束接触点的水平位置，并清除其切向速度，避免只改速度留下位置漂移。垂直接触保持单向约束，允许向上离地；未接地的节点继续进行软体形变和飞行。碎块可能因形变、翻转或离地弹起改变整体位置，止滑约束仅作用于贴地接触点。小于 1 时保留原有摩擦冲量计算。

新增斜向落地回归，覆盖 60/120 Hz：贴地点水平位移及速度为零，反弹和形变保留；空中运动与摩擦设置无关。全部 8 项碎块测试通过。


## 切面银色反光修复（2026-11-10）

切面此前与外皮共用高透射、强清漆的完整材质，反射环境时出现大面积银灰色。最初尝试使用静止姿态深度推算切面，但会漏掉切面边缘；现已改为切割资源自带的 surfaceGroups 标记：外表保留原材质，内部使用较低透射和清漆、更柔和的反光，并按实时身体颜色调制亮度，避免亮场景下过曝。遮罩随表面变形，旋转或落地不会改变内外材质区域；同一组仍合并为一个网格、一个材质。

`node tools/slime-fragments-material-check.mjs after` 可渲染九块不同朝向的碎块，截图位于 `analysis/slime-fragments/material-after.png`；修复前对照保存在同目录的 `material-before.png`。


### 银色问题复查：变形法线（2026-11-10）

此前仅覆盖 `normalNode`，更新的是主体材质法线。Three 的清漆法线在 NORMAL 子构建中仍可能读取 `normalViewGeometry`，因此继续使用未变形顶点法线；GPU 表面旋转、落地后，主体与清漆的光照方向不一致。现于顶点阶段同时更新 `normalLocal` 与位置，使清漆、几何光照与主体共享变形法线。

切面分类同步改用资源原始分组，覆盖位于外壳边界的切面顶点，保留真正外皮的光泽。止滑、反弹参数及求解器在本次修复中未改动。

验证：同一组九块旋转姿态，对比 GPU 渲染与 CPU 变形后的标准材质渲染，前景 RGB 平均通道误差 0.0203/255，通道差超过 12 的像素占比 0.0423%；原先银灰条带已消除。Chrome 实际爆炸落地画面亦确认，构建与 9 项碎块测试通过。对照入口 `tools/slime-fragments-material-check.mjs` 已加入 GPU/CPU 图像误差断言。

`tools/slime-fragments/contact-audit.ts` 另对比两种摩擦的落地应力：较强碰撞下两种模式均可能出现瞬时局部四面体反转，不能仅据此将银色归因于止滑。异常清漆反光在完全不接地的刚性旋转中也能复现，并由上述法线修正消除；本次没有声称解决所有极端碰撞的单元反转问题。


## 实心果冻重量感（2026-11-10）

按「明显压缩 → 低回弹 → 贴地晃动收稳」调整：地面额外反弹默认及保存值设为 0，体积可压缩度设为 0.05，保留原有软度、爆开速度与重力。

新增两个可保存的侧边栏参数：

- **撞地耗能**：默认 18 /s。向下的实际碰撞激活约 0.3 秒的衰减响应，消耗内部振动及整体向上的回弹能量，不削减入射下落速度。
- **贴地收稳阻尼**：默认 5 /s。有地面支撑时加速内部晃动衰减；接触点止滑与垂直反弹继续由原接触约束处理。

使用指数速度衰减，不播放预制压扁动画，也不冻结节点。状态在碎块复用出生时清空，首次接触前的运动不受两个新参数影响。关闭两个新参数可单独对照碰撞耗能的效果。

九块同高度落地对照中，最大离地高度均小于旧版的一半；峰值形变仍大于 10%，最终体积偏差小于 8%，后期运动量均低于旧版的 20%。具体弹起次数随形状、碰撞姿态和调参变化，不固定为动画次数。报告：`analysis/slime-fragments/weight-comparison.json`；复测入口：`npx tsx tools/slime-fragments/weight-check.ts /tmp/weight.json`。

构建、11 项碎块测试和 Chrome 实际爆炸/参数保存/回收验证通过。


## 增加数量与不均匀切割（2026-11-10）

从 9 块更新为 20 块，使用偏心、非网格的加权分区：大、中、小碎块混合，体积约 0.41–4.41 u³，最大/最小约 10.8 倍。随机种子固定为 74123，便于复现；每次爆炸沿用该组预切割资源，并映射到当次身体姿态。

78 个共享切面成对生成，保留鼓起的曲面。总体积与参考身体相差约 0.005%，姿态绑定重建误差小于 2e-14 u。切面仍使用原始标签，GPU 法线、落地止滑和实心果冻耗能均保留。

增加块数的同时调整曲面细分和物理笼密度：91,520 个表面三角形、1,125 个节点、3,917 个四面体。三组同时模拟的独立 CPU 基准中，求解中位耗时 5.74 → 6.73 ms，表皮 CPU 更新 0.87 → 1.05 ms。每组仍只提交一个绘制网格。

完整生成流程见 `tools/slime-fragments/README.md`。运行时和测试从 `manifest.json` 读取块数，不再固定为 9。旋转预览截图见 `analysis/slime-fragments/material-twenty-pieces.png`。
