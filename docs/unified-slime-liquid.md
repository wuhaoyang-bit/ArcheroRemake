# 融合液面、爆开液滴与湿脚步

游戏和爆炸调试页的「液体渲染方式」新增 2：融合液面 · 液滴与交互，并作为当前参数及新默认值。0 为原 Canvas，1 为 CurveFluid；切换不删除主液滩，新模式额外生成的落滴积液保存在自身系统中，切回新模式可继续显示。重置清空三套渲染状态。

实现按三步连接：

1. `slime-liquid-field.ts` 将主液滩和落点写入共享的覆盖/线性颜色场。柔和足迹累加，覆盖范围相接后统一着色，避免独立网格的内部接缝。混合区按贡献权重混色，不加入白色。`unified-slime-liquid.ts` 用 WebGPU/TSL 从覆盖场计算表面法线与圆润边缘。这是视觉融合，并非体积流体模拟。
2. 爆炸液滴由 `slime-liquid-drops.ts` 绘制：每滴两个三角形，面向当前相机，按屏幕速度投影拉伸；解析轮廓从圆头延伸为细尾。直接移植 INKWAVE 的透光、深色透镜边缘、环境反射、两层太阳高光，以及出生增长、运动抖动、寿命末端收缩。飞行趋势与眼球共用 `slime-flight-motion.ts`：出生初速度、可编辑的径向速度曲线和独立重力；相同起点/方向/参数时，触地前轨迹一致。液滴方向仍为向四周散射，大小/数量随爆开体型增长。首次触地即移除主体液滴并留下液滩，约 0.28 秒铺开；保留原有少量二次飞溅、波纹与融合，二次飞溅不继续制造积液。液滴不使用眼球的弹性、滚动阻力、怪物/玩家反弹或踢飞规则。碰到场地边缘时停止向外运动，随后落地，不做弹性反射。当前不制作墙面挂液或怪物身体贴花。
3. 落滴/脚步记录波纹事件，共享液面材质中向外传播并衰减。波纹受液体覆盖限制。玩家实际移动每约 0.65 单位采样一次左右脚位置，湿地才产生涟漪及少量小液滴；静止不重复触发。当前为步距近似，并未绑定角色脚骨。

参数在「撑爆 · 液体残留」/调试页「地面液滩」：液滴数量、涟漪力度、踩踏开关。液滴飞行参数独立于眼球：`liquidEjectSpeed`、`liquidGravity`、`liquidCurveTime`、`liquidSpeedCurve`。默认值取分离时当前保存的眼球参数：20 u/s、20 u/s²、0.9 s，以及 120% → 8% 的两点曲线。游戏在「撑爆 · 液体残留」调节，调试页在「地面液体 · 外观与展开 → 液滴 · 飞行」调节，含可编辑速度曲线；两页保存/导入/撤回或恢复默认均处理独立液滴参数。游戏修改从下一次出生生效，已飞出的液滴保留出生快照；调试页修改后重算当前预览。新增 `liquidSpeedJitter`（液滴速度随机偏移，默认 ±3 u/s，范围 0–40）：每滴出生时独立取一次基础速度上下偏移，负值截为 0，随后整条速度曲线使用这个随机后的基速；不逐帧重新随机。设为 0 关闭速度差异，固定随机种子可重复预览。二次飞溅/踩踏小滴保持自身喷射速度，出生时读取液滴重力。旧参数文件缺少这些键时，一次性复制文件中已有的眼球值（曲线深拷贝）；保存后互不关联。旧 `liquidDropSpeed` 已退出控制和默认配置，旧文件中的该字段忽略。已有目标直径、偏移、寿命、淡出、粗糙度继续生效。怪物颜色在爆开时保留到主液滩、液滴和落点；脚步飞溅取脚下融合后的颜色。

液滴保持怪物的线性 RGB 输入；照明公式与原版相同，环境颜色改用游戏的主光及半球光。液滴材质内采用原版 Neutral 色调映射。WebGPU r186 在全屏输出阶段执行色调映射，不能依靠 `material.toneMapped=false` 跳过；游戏与爆炸调试页因此统一为 Linear / exposure 1，防止调试页 ACES 二次处理。这也使调试页其它材质的色调处理与游戏一致。阴影通道使用同一位置变换及水滴轮廓裁切，避免矩形投影。未接入原版整屏 bloom/调色。

预算：384 个飞行液滴（共享实例批次，每滴由 168 降到 2 个三角形），256 个额外落点，最多最近128个主体足迹，16个并发波纹。液滴完整尺寸受速度、出生增长及寿命末端收缩影响；不会通过细分网格增加曲面成本。共享纹理384×768，发生覆盖变化时最多30Hz重新生成/上传；静止无限寿命液滩不持续上传。渲染几何为液面平面，厚度/波纹通过法线表现。尚未做 Android 真机性能验收。

验证：`tests/unified-slime.test.ts` 覆盖融合、颜色、落滴、容量、过期、踩踏和切换；`tools/unified-slime-browser-check.mjs` 验证 WebGPU 实际渲染；`tools/unified-slime-game-check.mjs` 检查实际怪物爆开、残留、游戏踩踏连接、渲染切换和重置。`tools/slime-drops-parity-check.mjs` 读取本地 INKWAVE 的实际 GLSL，在相同镜头、颜色、速度及照明下与 TSL 作像素核对，涵盖四种颜色、静止/多方向速度、出生/抖动/末端淡出。内部像素与轮廓分别比较，允许 WebGL/WebGPU 的 MSAA 边缘有 1px 差异。可用 `INKWAVE_FX_SOURCE` 指定源码路径，默认 `../INKWAVE-preview/src/fx/fx.js`。截图分别位于 `analysis/unified-slime/`、`analysis/unified-slime-game/` 和 `analysis/slime-drops-parity/`。

`tools/slime-drops-lab-check.mjs` 检查实际爆炸调试页的色调映射、飞行液滴与阴影，保存透视、正面和俯视截图到 `analysis/slime-drops-lab/`。着色器移植时原版同条件比对的内部颜色最大差异为 1/255，轮廓差异不超过 1px。

`tests/slime-liquid-motion.test.ts` 从两个实际系统创建相同出生位置、方向、半径的眼球与液滴，在 30/60/120Hz 下核对触地前的位置/速度；验证液滴第一次落地就移除并形成水滩、眼球继续反弹，且眼球弹性参数不影响液滴。还覆盖零曲线仍受重力、无弹性墙边处理、出生参数快照和粒子池满载。眼球原有形变/踢飞测试同时保留。

`tests/slime-liquid-settings.test.ts` 覆盖独立默认值、旧文件迁移、保存往返、有效值校验、曲线深拷贝。运动测试显式设定相同值检查眼球/液滴的空中轨迹，也设定不同值检查双方独立。浏览器检查覆盖游戏参数/曲线编辑与撤回、调试页独立重力/曲线编辑、保存/导入，并在实际爆炸后核对两套系统各自读取的参数。
