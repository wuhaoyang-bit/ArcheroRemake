# ArcheroRemake

第一版：用 **Three.js + WebGPU** 复刻《弓箭传说》的角色轮盘移动手感。电脑用鼠标，手机用触摸；两端保持相同的 9:19.5 竖屏构图。具体规则、用户原话与验收依据见 [PLAN.md](PLAN.md)。

## 运行

需要 Node.js 22.12+（已在 Node.js 24 上验证）和可用 WebGPU 的浏览器。

```sh
npm ci
npm run dev
```

电脑打开 `http://localhost:5173`。按住游戏区域任意位置：先原地跑步，拖出首次解锁距离后开始移动；松开立即停止位移。左侧调参，右侧观察状态。

## 保存参数

修改参数会即时生效。点击面板底部的 **保存 JSON**，将当前全部调参值写入项目的 [`public/params.json`](public/params.json)。刷新或重新打开页面时读取这份文件；电脑与同一开发服务下的手机共用它，不依赖浏览器本地缓存。

保存方式参考 SmashBroCER：页面提交参数，Vite 的保存接口写回固定 JSON 文件。文件采用版本化结构，写入时校验数值并以临时文件原子替换，避免写入失败损坏之前的保存；保存不会触发整页重载。面板会显示未保存、保存成功或失败状态。

**恢复默认**仅把当前页面调回下表的默认值；希望下次打开也用默认值时，再点击 **保存 JSON**。尚未保存的修改在刷新后丢弃；多个页面同时保存时，以最后一次成功写入为准，其他页面刷新后读取。仅保存调参值，角色位置、按下状态和移动锚点记忆在刷新后仍清零。

`npm run dev`、`npm run dev:https` 与 `npm run preview` 均支持写回本项目的 `public/params.json`。纯静态部署可读取构建时打包的 JSON；若要在线保存回服务器，需要提供对应保存接口。

## 手机测试

手机和电脑连接同一局域网，然后运行：

```sh
npm run dev:https
```

打开终端显示的 **Network HTTPS 地址（5174 端口）**。手机右上角“调参”按钮展开参数面板。轮盘以最新按下的手指为准，支持多指接管。

WebGPU 需要安全上下文：电脑可使用 localhost；手机通过局域网 IP 访问时需要 HTTPS。开发服务使用自签名证书，手机需要信任该证书；如果浏览器仍不认可该连接，应使用受信任证书的 HTTPS 地址。支持程度以设备实际能否创建 WebGPU 适配器为准。页面会显示初始化失败原因，不会悄悄切换为 WebGL。当前自动化覆盖桌面 WebGPU、手机视口和浏览器多点触摸；**手机真机性能与手感仍需实际设备验收**。

## 离线 Android APK

目标测试机为 REDMI K80 Ultra。APK 直接装入同一次构建的网页、模型和 `public/params.json`，使用系统 WebView 的 WebGPU 渲染，保留相同的竖屏视角、触摸逻辑和调参界面。首次启动读打包的 JSON；点击“保存 JSON”后写入应用私有目录，退出重开仍有效，不需要电脑或服务器。之后电脑修改 JSON 不会自动同步到已安装的 APK。

覆盖安装且签名一致时保留手机已保存参数；卸载或清除应用数据会删除它们。恢复默认与网页规则一致：先恢复当前值，再点击保存。只有参数持久化，角色位置及锚点记忆不保存。

构建需要 JDK 17、Android SDK Platform 36 / Build Tools 36.0.0，并设置 `JAVA_HOME`、`ANDROID_HOME`。当前电脑在忽略目录 `analysis/android-toolchain/` 已准备工具链，脚本会自动识别。

```sh
npm run android:build
# 输出 releases/ArcheroRemake-v0.1.0-debug.apk
```

这是供直接安装测试的 debug 签名包。脚本首次生成的本地测试签名位于 `analysis/android-toolchain/archero-debug.keystore`；请保留它，以便后续覆盖安装。SDK、密钥、构建缓存和 APK 均不纳入 Git。构建前会校验网页资源复制后的每个字节，并保留资源 SHA-256 清单。

手机仍须有支持 WebGPU 的系统 WebView；不支持时显示错误，不降级为 WebGL。相同代码、素材和参数可通过构建校验确认，REDMI K80 Ultra 的实际画面、触摸延迟和帧率仍需真机验收。安装后可断网测试移动、多指接管、保存后重开，以及切到后台再返回时是否正确结束输入。

## 已实现

- 按下点定位轮盘、首次阈值锁定、越阈值瞬时解锁、边缘限幅；解锁后不重复触发死区。
- 待机／原地跑步／真正移动，与摇杆锁定状态分开管理。
- 固定速度、立即位移、身体按最短角度转向；松手后身体继续转完。
- 正常松手以该事件携带的最终鼠标／触点坐标直接计算锚点（经过半径限制与地面映射，不读取摇杆显示位置），再立即停止位移；目标朝向始终由锚点决定，待机时也继续转完；旧手指松开和取消操作不会覆盖当前方向。失去指针捕获时立即停止位移，但保留同次操作的收尾信息，仍接受随后到达的最终松手坐标；新按下、取消或窗口失焦会清除待收尾信息。
- 可见移动锚点、角色相对偏移记忆、松手隐藏；精确居中时保留最后方向继续移动。
- 最新手指接管；移动中换指延续旧方向，直到新摇杆解锁；旧指永不恢复控制。
- Idle／Run 骨骼动画融合；中途反向融合从当前权重继续，原地跑步进入移动不重启动画。
- Run 动画播放倍率独立可调，原地跑步与真正移动共用该倍率；Idle、融合时长、实际位移速度各自独立。
- 宽度与纵向长度独立可调的长房间；固定横向镜头，仅纵向平滑追近，房间上下边缘不截断跟随。
- 地面两轴同尺度映射，再由倾斜正交镜头自然投影；没有第二次纵向压缩或逆向角度补偿。
- 指针捕获、失焦／取消清理、屏幕边缘轮盘保持原始按下位置、调参控件隔离。

本版没有攻击、敌人、关卡系统或键盘移动。

## 可调参数

像素以 390 宽的游戏视口为基准，在不同设备上等比换算。世界单位仅用于本项目。

| 参数 | 初值 | 含义 |
| --- | --- | --- |
| 摇杆半径 | 64 px | 摇杆最大偏移 |
| 首次解锁距离 | 12 px | 每次按下／接管后需严格超过该距离 |
| 地面映射比例 | 0.036 单位/px | 限幅后的摇杆偏移到地面两轴的统一比例 |
| 移动速度 | 16 单位/s | 可调范围 1～30；与摇杆幅度、身体朝向无关 |
| 转向速度 | 900°/s | 身体最短角度转向速度 |
| 动画融合 | 0.06 s | Idle／Run 的姿态融合时长 |
| Run 动画速度 | 1.6 倍 | 可调范围 0.25～4；只改变 Run 播放节奏 |
| 房间宽度 | 16 单位 | 横向边界；角色脚下留 0.46 单位碰撞半径 |
| 房间纵向长度 | 38 单位 | 画面上下方向，可独立调整至 8～80 |
| 显示移动阈值范围 | 关闭 | 黄圈表示首次解锁范围，解锁后变青色；开关随 JSON 保存 |
| 跟随响应 | 9 s⁻¹ | 按位置差指数收拢，越大越紧跟 |
| 脚下目标线 | 0% | 默认画面中线；正值下移，负值上移 |
| 固定视野宽度 | 18 单位 | 手动校准；游玩中不自动缩放 |

默认镜头为倾斜正交投影，高度 24，相对地面的俯视夹角约 55.1°，使地面两轴的屏幕投影长度比约为 0.82。此数值只用于本版画面初始校准，不代表已经证明原作的内部参数。刷新后调参值从 JSON 恢复，角色运行状态和锚点记忆重新初始化。

## 验证与构建

```sh
npm test
npm run build
```

浏览器检查需要先启动开发服务及可用的 Chrome：

```sh
npm run test:browser
# 松手坐标比最后一次移动更新时，最终朝向与锚点记忆的专项回归：
npm run test:release
# 两个开发服务都运行时，同时验证 HTTPS 入口：
HTTPS_URL=https://localhost:5174 npm run test:browser
# JSON 保存、刷新恢复、跨浏览器共享和 Run 倍率：
HTTPS_URL=https://localhost:5174 npm run test:settings
```

macOS 默认使用 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。其他路径可设置 `CHROME_PATH`；也可 `npx playwright install chromium` 后使用 Playwright 浏览器。`BASE_URL` 可覆盖默认开发地址。测试的 WebGPU 开关仅用于无头浏览器，应用本身不依赖该启动参数。

状态测试覆盖阈值、位移、转向、锚点、换指、精确居中、动画融合、房间约束和帧率一致性。浏览器检查通过真实指针事件及 Chrome 多点触摸事件验证输入、画面比例、镜头投影、控件隔离和 HTTPS 加载。截图和结果写入本地 `analysis/v1-checks/`，不纳入 Git。

松手专项检查通过 Chrome 输入事件直接发送新的松手坐标，不补发最后一次移动，覆盖重复释放、不同最终方向、锚点记忆、精确居中及取消操作。结果写入本地 `analysis/release-checks/`。

生产构建输出到 `dist/`，可部署到 HTTPS 静态服务器；`npm run preview` 在本机预览构建。开发时的只读检查接口不会出现在生产构建中。

## 旋转角速度模型对比

左侧“角色 → 旋转角速度模型”包含五个选项：匀速转向、指数跟随（原有实验）、自定义转向曲线、指数阻尼（独立参数）、带速度状态的阻尼。原有三套参数和当前已保存的选择保持原样；全新配置的默认选择仍为匀速 1200°/秒。

原有指数跟随与新增指数阻尼使用相同的纯指数公式：每步转角 = 最短角差 × (1 − exp(−响应系数 × dt))。两套参数独立保存，原有实验及由它生成的自定义曲线不会被新默认值覆盖。

本次校准按用户确认优先“第 9 帧进入 0.1°，允许前半段更快”，不再要求第 4 帧恰好转过 90°。前提是 180° 固定目标、初始角速度为 0、60 FPS；实际模拟按现有最大 1/120 秒子步运行。

| 新模型 | 默认参数 | 第 4 帧已转过 | 第 9 帧 |
| --- | --- | --- | --- |
| 指数阻尼 | 响应 50 /秒，到位阈值 0.1° | 约 173.6° | 对齐目标 |
| 带速度状态的阻尼 | 平滑时间 0.03039 秒，到位阈值 0.1° | 约 168.0° | 对齐目标 |

指数响应由 ln(180 / 0.1) / (9 / 60) ≈ 49.97028 求得，向较快方向取 50。速度阻尼按 Unity SmoothDamp 的不限速数值递推求解，平滑时间约 0.03039237 秒，向较快方向取 0.03039。到位阈值让有限时间内完成对齐，不改变移动锚点；平滑时间不是固定转向时长，持续变化的目标也不保证 9 帧完成。

速度阻尼保存有符号角速度状态，松手、换指与待机不会清除它。继续沿当前锚点转向；到位后清零速度。目标改到相反旋转路径时清除反向惯性，以维持既定最短路径；切换模型时清零内部速度，但不重置位置、身体朝向、锚点或输入。水平精确 180° 仍为左转右经上侧、右转左经下侧，其余情况取最短路径。

新增可调字段 dampingResponse、dampingSnapAngle、velocitySmoothTime、velocitySnapAngle 随“保存 JSON”持久化。旧 JSON 缺少字段时自动补默认；内部角速度状态不写入 JSON。调参面板只显示当前模型参数，其他参数保留。此次只更新网页，不生成 APK。

验证命令：npm test、npm run build、npm run test:turn-model；TURN_MODEL=3 npm run test:release 与 TURN_MODEL=4 npm run test:release 检查新增模型的松手、捕获丢失事件顺序。浏览器保存测试使用隔离数据，不写入实际调参文件。

自定义转向曲线：在「旋转角速度模型」选择第三项。横轴从180°到0°，纵轴为°/s；双击空位加点、双击点编辑数值，也可拖动或放大编辑。0°与180°端点不可删除，速度可自由编辑。内部点选中后可删除。按「保存参数」将曲线与所选模型写入JSON。

默认曲线从现有指数参数生成，转向计算与指数模型一致；之后两者独立。使用「从当前指数参数生成曲线」可重新生成并复制到位阈值。非零角度设为零速度可能导致停转，编辑器会提示。到达0°时始终停止，不受0°端点速度数值影响。
